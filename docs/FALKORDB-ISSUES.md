# FalkorDB issues and workarounds

Every FalkorDB limitation, quirk or default we hit and are bypassing or patching around. Each entry gives what we saw
(exact error where there is one), what we do instead, where the workaround lives, and when to revisit it.

Environment: `falkordb/falkordb:v4.20.7` (C engine), Python client `falkordb==1.7.1`, sponsor MCP server
`falkordb/mcpserver:1.3.0`. Everything below was reproduced on this setup unless marked *unverified*.
**Re-test the whole list before upgrading** (v4.22.x or the 6.0 Rust engine); some may be fixed.

## Not FalkorDB bugs (standard behaviour that bit us)
- `count()` over zero matched rows still returns one row (`0`). An absence proof built on a bare count "proved" no
  warning for a crash id that doesn't exist. Fixed by grouping on the matched node so an unknown id returns no rows
  (`queries.PROVE_NO_LINKED_WARNING`). This is ordinary Cypher aggregation, but it matters for fail-closed checks.
- A named path `p = (a)-[:R*]->(b)<-[:S]-(c)` includes **every** node of the pattern, `c` too. Our step chain picked up the
  Investigation as a fake last step. Bind the endpoint first and path only over `NEXT` (`memory.steps`).
- Redis ACL key patterns (`~ws_*`) **do** apply to FalkorDB graph commands (graph name = key). A ws_writer write to `ntsb`
  gets `NOPERM No permissions to access a key`; redis-py shows it as `NoPermissionError: No permissions to access a key`
  without the `NOPERM` prefix, so match on the exception type.

## Versions deliberately not used
- **FalkorDB 6.0.x** (new Rust engine, released 29 Sep 2026). Too new for the build; revisit after the event and re-run this list plus `make eval`.
- **MCP Python SDK 2.x.** This one isn't FalkorDB: `langchain-mcp-adapters` 0.3.2 requires `mcp<2`, so we're on 1.30.0.
